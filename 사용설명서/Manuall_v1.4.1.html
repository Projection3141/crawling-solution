01 / START처음 시작하기

설치 파일 MallCollectorSetup-1.4.1.exe로 설치한 뒤 Mall Collector를 실행합니다. 앱 상단의 버전 표시를 확인하세요.

1. 준비계정 · API 키 등록
2. 수집사이트 · 범위 선택
3. 저장 확인실행 현황 · 결과 폴더
4. 전송 확인전송 ON · 응답 확인
  1. 환경설정 → 계정 등록 및 관리
    수집할 쇼핑몰에서 사용하는 로그인 계정을 등록합니다.
  2. 환경설정 → API 키 등록 및 관리
    제공받은 OpenAI API 키를 등록합니다. 현재 앱은 일반·상세 수집 모두 키 선택이 필요합니다. 새 번역은 상세 수집에서 수행합니다.
  3. 천유에서 프록시를 사용하는 경우 등록
    프록시 등록 및 관리에서 연결 주소와 필요한 인증정보를 등록합니다. 프록시는 수집에 사용하는 인터넷 연결 경로입니다. 과자생각은 직접 연결합니다.
  4. 새 수집 → 결과 기본 폴더 확인
    폴더 선택으로 결과를 보관할 위치를 지정합니다. 기본 위치는 C:\Users\사용자명\MallCollector입니다.
수집 완료와 서버 전송 완료는 다릅니다.수집은 먼저 PC에 파일을 저장합니다. 서버 반영은 별도의 전송 기능이 처리하므로, 저장 파일과 전송 내역을 각각 확인하세요.

02 / WHAT’S NEW1.3.0 이후 변경점

기존 사용자가 알아두면 좋은 변경점입니다. 아래 사용 방법에는 모두 반영되어 있습니다.

1.3.1–1.3.2 · 일정 / 전송

특정 시각 실행 · 전송 분리

매일 정해진 시각에 수집할 수 있습니다. 수집 결과는 먼저 저장하고, 별도의 수집정보 서버 전송 버튼으로 1시간 주기 전송을 켜거나 끕니다.

1.3.1–1.3.4 · 안정성

누락 재시도 · 연결 자동 교체

중간 저장과 페이지 단위 누락 재시도를 보강했습니다. 대기시간을 조정하고 프록시·브라우저를 교체하며, 실패가 2회 누적되면 다음 실행은 역순으로 진행합니다.

1.3.5–1.4.0 · 상세 수집

신규 상품 모드 · 수집 범위 제한

천유의 신규·상세 미수집 상품 모드가 추가되었습니다. 전체 상세 수집은 실행당 최대 20페이지이며, 페이지마다 연결을 교체하고 상세 수집에도 예외 처리를 적용합니다. 아카이브도 앱 버전별로 구분합니다.

1.4.0–1.4.1 · 가격 / 데이터

가격 갱신 · 저장 형식 통일

천유 일반 수집에서 1개 적용 도매가를 갱신하고, 상세 수집에서 소비자가를 저장합니다. 원화와 엔화 가격, 이미지 3종, SKU, 생성·갱신 시각을 구분해 저장하며 일부 미사용 키를 정리했습니다.

1.4.1 추가 보완: 과자생각도 페이지별 중간 저장을 지원하고 주요 스펙 6종의 일본어 라벨을 고정했습니다. 사이트별 병합·번역 캐시를 분리하고, 임시 파일 작성 후 교체하여 기존 아카이브를 보호합니다.

장시간 운영 개선: 환율·번역 장애 시 수집값을 보존하고 경고합니다. 반복 일정은 최초 실행 시각 기준으로 계산하며 시작 실패 시 재시도합니다. 최소화 상태의 타이머 제한과 브라우저 추적 자원을 정리하고, 운송 조회 대기·재시도를 제한하며 상품 아카이브를 우선 전송합니다.

03 / COLLECT상품 수집하기

먼저 목적에 맞는 수집 방식을 고릅니다.

일반 수집

가격과 판매·품절 상태를 자주 갱신할 때 사용합니다. 천유는 옵션별 재고와 1개 적용 도매가도 확인합니다. 과자생각은 정확한 재고 개수 대신 판매·품절 상태를 수집합니다.

상세 수집

일반 수집을 거친 뒤 상품 설명, 이미지, 바코드, 소비자가, 상세 스펙 등을 보충합니다. 필요한 상품명은 일본어·영어, 옵션명은 일본어로 번역합니다.

  1. 새 수집에서 쇼핑몰 사이트와 계정을 선택합니다.
    카테고리는 코드 또는 상품 목록 URL을 입력합니다. 비우면 전체 카테고리를 사용합니다.
  2. 시작 프록시 설정과 OpenAI API 키를 선택합니다.
    천유 프록시를 사용하지 않으면 프록시 사용 안 함을 선택합니다.
  3. 수집 방식과 수집 브라우저 표시를 선택합니다.
    처음 확인할 때는 표시를 선택하면 로그인·진행 화면을 볼 수 있습니다. 숨김이어도 수집은 진행됩니다.
  4. 페이지 범위 및 고급 공통 설정을 펼칩니다.
    아래 표에 맞춰 페이지 범위와 상세 수집 모드를 설정합니다. 처음에는 1~2페이지로 결과를 확인하면 좋습니다.
  5. 실행 방식에서 1회 실행을 선택한 뒤 수집 실행 추가를 누릅니다.
    실행 현황에서 진행 상황과 완료·실패·경고 내용을 확인합니다. 1회 실행은 해당 작업이 끝나는 방식이며, 앱을 종료하는 설정은 아닙니다.
설정사용 방법
일반 수집 범위시작 페이지는 1 이상. 종료 페이지 0은 마지막 페이지 자동 감지입니다.
상세 → 범위 내 전체 상품기존 상품까지 상세 정보를 다시 갱신합니다. 종료 페이지를 직접 입력하고 한 작업은 최대 20페이지로 설정합니다. 예: 1~20, 다음 작업은 21~40.
상세 → 신규·상세 미수집 상품천유 전용입니다. 신규·상세 실패·데이터 형식 변경으로 재확인이 필요한 상품을 수집합니다. 종료 페이지 0을 사용할 수 있고 20페이지 제한이 없습니다. 최초 실행에는 기존 상품도 포함될 수 있습니다.
과자생각 상세 수집범위 내 전체 상품 방식으로 설정합니다. 종료 페이지를 지정하고 20페이지 이내로 나눕니다.
상세 페이지 지연(ms)상품 상세 요청 사이의 대기시간입니다. 1000ms는 1초입니다. 천유는 입력값의 70~160% 범위로 적용합니다.
브라우저 User-Agent천유 수집·장바구니에 적용되는 브라우저 식별값입니다. 별도 안내를 받지 않았다면 비워 기본값을 사용합니다.
같은 사이트·같은 계정의 작업이 겹치면 시작이 제한될 수 있습니다.기존 수집 또는 장바구니 작업이 끝난 뒤 추가하세요. 현재 작업을 멈추려면 실행 카드의 이 실행 취소를 누르고 취소 상태를 확인합니다.

천유 일반 수집은 등록 프록시를 10페이지마다 순환하며, 상세 수집은 목록 페이지별로 프록시와 브라우저 컨텍스트를 교체합니다. 페이지 전환과 누락 재시도 중에는 대기시간이 포함될 수 있습니다.

04 / SCHEDULE반복 수집하기

실행 방식을 중지 전까지 반복 실행으로 바꾸고 반복 일정을 선택합니다.

목적설정 예시기준
하루 3회 재고·가격 갱신일반 수집 → 일정 주기마다 실행 → 8시간첫 실행 시각부터 8시간 간격
매일 같은 시각에 갱신매일 일정 시각에 실행 → 09:00선택한 시각에 다음 실행 예약
주 1회 기존 상품 상세 갱신상세 → 범위 내 전체 상품 → 1주20페이지 이내 범위로 작업 분리
예: 오전 9시에 시작하고 8시간 간격으로 설정했다면첫 작업이 오전 10시에 끝나도 다음 실행은 오후 5시입니다. 완료 시각이 아닌 최초 실행 시각을 기준으로 계산합니다. 오래 걸려 지나간 회차는 건너뛰며, 시작에 실패하면 1~5분 간격으로 재시도합니다.
  • 실행 현황에서 다음 예약 시각을 확인하고, 반복을 끝낼 때는 반복 중지 기능을 사용합니다.
  • 앱은 계속 켜 두어야 합니다. 창을 최소화해도 타이머 제한을 받지 않도록 개선했지만, PC 절전·종료 중에는 실행되지 않습니다.
  • 앱 재시작이나 화면 새로고침 후에는 반복 예약이 자동 복원되지 않습니다. 다시 설정하세요.

05 / RESULTS저장 결과 확인하기

  1. 실행 현황에서 완료 상태와 경고를 확인합니다.
    완료되어도 일부 상품 누락이나 번역 경고가 있을 수 있습니다. 수집 수량과 메시지를 함께 봅니다.
  2. 실행 카드의 결과 폴더 열기를 누릅니다.
    실행별 파일은 결과 기본 폴더 아래 사이트/실행 ID/에 저장됩니다.
  3. 상품 하나를 골라 가격·판매 상태·이미지를 대조합니다.
    상세 수집이라면 소비자가와 설명 이미지가 채워졌는지도 확인합니다.
파일쉽게 보는 용도
result.json이번 실행 대상 상품에 기존 아카이브 정보를 병합한 결과입니다. 상품 객체의 배열로 저장됩니다.
inventory.csv / summary.csv옵션별 재고·가격 관측값 또는 판매 상태 / 상품별 재고 요약을 표로 확인합니다.
products.csv목록에서 수집한 상품 정보를 확인합니다.
details.csv / detailResult.json상세 수집 원본 / 이번에 상세 수집을 시도한 상품의 병합 결과입니다.
result_translated.json상세 수집의 번역 단계가 성공했을 때 생성되는 번역 결과입니다.

아카이브는 누적 상품 보관 파일입니다

기본 경로는 C:\Users\사용자명\MallCollector\archive\v1.4.1_archive.json입니다. 두 사이트 데이터를 한 파일에 보관하되 사이트와 상품 ID를 함께 확인해 병합합니다. 실행별 결과와 누적 아카이브는 상품 수가 다를 수 있습니다.

버전별 아카이브를 확인하세요.1.3.5부터 실행 PC의 아카이브도 앱 버전별로 분리합니다. 업데이트 후에는 현재 버전 파일과 수집 결과를 확인하세요. 저장 시 임시 파일을 먼저 작성하고 교체하여 저장 실패로 기존 파일이 손상될 가능성을 줄였습니다.

천유는 수집 차수별로, 과자생각은 목록 페이지별로 중간 저장합니다. 상세 원본도 번역 전에 저장합니다. 중단 시점까지 모든 상품이 저장되었다는 뜻은 아니므로 실제 파일과 수집 수량을 확인하세요.

06 / TRANSFER서버 전송하기

앱 상단에 서로 다른 전송 스위치가 있습니다. 필요한 전송이 ON인지 각각 확인합니다.

수집정보 서버 전송

누적 상품 아카이브를 서버로 보냅니다. ON 상태에서 앱 실행 직후 전송을 시도하고 이후 1시간마다 전송합니다. 개별 수집이 끝날 때마다 즉시 보내는 방식은 아닙니다.

운송정보 서버 전송

운송장 등 운송정보를 조회해 서버로 보냅니다. 상품 전송과 별도로 켜거나 끌 수 있습니다. 운송 조회 대기·재시도에 제한을 두고 상품 아카이브를 먼저 전송하도록 개선했습니다.

  1. 환경설정의 Upload API URL을 확인합니다. 변경이 필요한 경우 담당자에게 받은 주소를 입력하고 저장합니다. 이 주소는 장바구니 조회·운송정보 전송·수집정보 전송에 공통으로 사용됩니다.
  2. 앱 상단의 수집정보 서버 전송을 ON으로 둡니다.
  3. 전송 내역 → 수집정보 전송 내역에서 실제 요청과 서버 응답을 확인합니다. 필요한 경우 로그 폴더를 열어 날짜별 기록을 확인합니다.
전송 ON은 전송 성공 표시가 아닙니다.서버 오류나 네트워크 문제로 실패할 수 있습니다. 수집 파일이 저장되었더라도 서버 응답은 따로 확인해야 합니다. OFF로 바꾸면 상품 전송이 중지되며 수집 결과는 PC에 저장됩니다.

07 / CART장바구니 일괄 담기

서버에서 받은 상품 목록을 선택한 사이트 계정의 장바구니에 담는 기능입니다.

  1. 장바구니 담기 메뉴를 엽니다.
    대상 상품이 있는 사이트의 계정을 선택합니다. 천유는 필요하면 프록시도 선택합니다.
  2. 장바구니 담기 버튼을 누릅니다.
    서버에서 상품 ID·옵션·수량 목록을 받아 자동으로 처리합니다. 같은 계정의 수집이 실행 중이면 완료 후 진행합니다.
  3. 완료 메시지와 실제 장바구니를 확인합니다.
    품절·수량 부족·옵션 누락으로 일부 상품이 건너뛰어질 수 있습니다. 상품별 옵션과 담긴 수량을 대조합니다.

주문 요청 목록이 비어 있거나 불러오기에 실패하면 환경설정의 Upload API URL과 처리 메시지를 확인하세요.

08 / DATA GUIDE저장 데이터, 이렇게 읽으세요

JSON의 키는 데이터 항목 이름입니다. 두 사이트 모두 공통 형식을 사용하며, 수집하지 못한 값은 비어 있거나 null일 수 있습니다.

가격: 원화 2개 + 엔화 환산값 2개

키천유과자생각
originalPrice상세 수집의 소비자가(원)판매가(원)
wholesalePrice일반 수집 팝업에서 수량 1개를 적용한 도매 단가(원)판매가(원), originalPrice와 동일
yenOriginalsalePriceoriginalPrice를 엔화로 환산한 값. 키의 철자는 표시된 그대로 사용합니다.
yenWholesalePricewholesalePrice를 엔화로 환산한 값
currency원본 가격의 통화는 KRW입니다. 엔화는 별도 필드에 저장합니다.
가격 예시 · 이해를 위한 가상 환율천유 소비자가 8,500원, 1개 적용 도매가 5,525원, 1원 = 0.1엔이라면 소비자가 환산값은 850엔, 도매가 환산값은 553엔입니다. 정수 엔 단위로 반올림하며, 여러 개 구매할 때만 적용되는 할인가는 도매가로 선택하지 않습니다.

이번에 관측한 가격만 환산합니다. 천유 일반 수집은 기존 소비자가 환산값을 유지하고, 상세 단계는 기존 도매가 환산값을 유지합니다. 상세 실행에 앞서 수행하는 일반 수집에서는 도매가도 갱신합니다. 과자생각은 두 가격과 두 환산값을 각각 동일하게 저장합니다.

환율 조회가 실패해도 원화값은 저장합니다. 원화가 바뀐 항목은 과거 엔화값을 null로 비우고, 바뀌지 않은 가격의 엔화값은 유지합니다. 다음 해당 가격 수집에서 환율 조회에 성공하면 다시 채웁니다.

이미지는 용도별 URL로 구분합니다

키내용
thumbnailUrl목록에서 보여줄 썸네일 URL 1개. 없으면 메인 이미지로 보완합니다.
imageUrls상품 메인 이미지 URL 목록
descriptionImageUrls상품 설명에 들어가는 이미지 URL 목록

이미지 구분 저장은 이미지 주소를 데이터에 나누어 기록한다는 뜻입니다. 이미지 파일 자체를 PC의 세 폴더로 내려받는 기능을 뜻하지 않습니다.

SKU와 생성·갱신 시각

  • SKU: 상품 관리 단위의 식별값입니다. 옵션이 없는 상품은 CHEONYU-93060, CCDOME-1000005353처럼 사이트-상품ID로 저장합니다.
  • 옵션 상품: 상위 상품의 SKU는 빈 문자열이며, 각 options[].sku에 사이트-상품ID-옵션ID를 저장합니다. 옵션 ID가 없으면 SKU도 비워 둡니다.
  • createdAt: 최초 수집 저장 시각입니다. 이후 수집에서도 기존 시각을 유지합니다.
  • updatedAt: 이미 생성 시각이 있는 상품을 다시 수집·저장한 시각입니다. 최초 저장에는 null일 수 있고, 같은 실행에서 중간 저장 후 다시 저장해도 갱신됩니다. 번역만 갱신할 때는 두 시각을 바꾸지 않습니다.

시각은 ISO 8601 UTC 형식입니다. 끝의 Z는 UTC를 뜻하며, 한국 시각은 9시간을 더해 봅니다. 이 값만으로 전체 작업 완료 또는 마지막 상세 수집 성공을 판단할 수는 없습니다.

항목 이름의 번역을 고정한 것이며, 소비기한·배송비 같은 실제 값이 고정되는 것은 아닙니다.

구버전 데이터를 함께 확인하는 경우

yenPrice, adminMemo, convertTime은 상품 결과·아카이브·전송 필드에서 제거했습니다. 엔화값은 두 가격별 환산 필드로 확인하세요. slug는 현재 빈 문자열로 저장합니다.

기존 createdAt이 있으면 유지합니다. createdAt 없이 구버전 convertTime만 있으면 해당 시각을 ISO 형식으로 이전하므로, 과거 상품의 실제 최초 수집 시각과 같다고 단정하지 마세요. 기존 데이터에 새 엔화 필드가 없으면 다음 해당 가격 수집 때 채워집니다.

09 / HELP문제가 생겼을 때

수집이 멈춘 것처럼 보입니다.

페이지 전환 대기, 프록시·브라우저 교체, 누락 재시도 중일 수 있습니다. 실행 메시지와 진행 페이지를 먼저 확인하세요. 누락은 페이지 단위로 재시도하며, 재시도 후에도 누락되면 로그를 남기고 다음 수집으로 진행할 수 있습니다.

상품은 저장됐는데 서버에 보이지 않습니다.

앱 상단의 수집정보 서버 전송이 ON인지 확인하고 전송 내역에서 실제 서버 응답을 확인합니다. 수집 직후에는 다음 전송 주기를 기다려야 할 수 있습니다. 실패했다면 결과 파일과 전송 로그를 보관해 담당자에게 전달하세요.

상세 수집을 시작할 수 없습니다.

전체 상품 모드에서는 종료 페이지를 직접 입력하고 범위를 20페이지 이내로 설정해야 합니다. 신규·상세 미수집 모드는 천유에서만 사용할 수 있습니다. 계정과 API 키 선택, 같은 계정의 실행 여부도 확인하세요.

번역이나 엔화 가격이 비어 있습니다.

번역·환율 서비스 실패 경고를 확인합니다. 1.4.1은 원본 수집값을 먼저 보존합니다. API 키와 연결 상태를 확인한 뒤 필요한 상품을 다시 수집하세요. 일반 수집은 새 번역을 하지 않으므로 번역 보충에는 상세 수집을 사용합니다.

과자생각 재고 수량이 null입니다.

과자생각 일반 수집은 정확한 재고 개수를 수집하지 않습니다. saleStatus와 stockStatus로 판매·품절 여부를 확인합니다. null을 재고 0개로 해석하지 마세요.

신규 상품 모드인데 기존 상품도 수집됩니다.

첫 실행이나 데이터 형식 변경 후에는 기존 상품도 재확인 대상이 될 수 있습니다. 이미 성공한 상품의 상세를 주기적으로 다시 갱신하려면 범위 내 전체 상품을 사용하세요.

로그인이 실패하거나 같은 계정으로 시작할 수 없습니다.

계정 선택과 비밀번호를 확인하고 브라우저를 표시로 바꿔 로그인 화면을 확인합니다. 같은 사이트·같은 계정의 수집 또는 장바구니 작업이 진행 중이면 완료나 취소 후 다시 시작하세요.

예약 시간이 지났는데 실행되지 않았습니다.

PC 절전 여부와 앱 실행 상태를 확인합니다. 실행 중 지나간 회차는 건너뛰고, 시작 실패 시 재시도합니다. 앱을 재시작하거나 화면을 새로고침했다면 반복 예약을 다시 등록하세요.

설치 또는 실행이 차단됩니다.

배포받은 파일명과 오류 문구를 확인해 담당자에게 전달하세요. 회사 PC의 보안 정책으로 차단된 경우 사내 전산 담당자에게 해당 설치 파일의 검토를 요청합니다.

매일 확인할 항목

  • 수집할 사이트·계정·페이지 범위가 맞는지 확인
  • 실행 완료 상태, 수집 수량, 누락·가격·번역 경고 확인
  • 결과 파일과 현재 버전 아카이브 확인
  • 수집정보 전송 ON 상태와 실제 서버 응답 확인
  • 반복 작업의 다음 실행 시각과 PC 절전 설정 확인
  • 저장 공간 확인, 문제 발생 시 실행 ID·오류 메시지·관련 결과와 로그 보관
