Local Desktop Crawler Manual

쇼핑몰 상품 수집기
사용 설명서

천유닷컴과 과자생각의 상품·재고·상세 정보를 수집하고, 한국어·일본어·영어 번역 데이터를 생성하며, 상품 수집 결과와 운송장 데이터를 서버로 전송하는 데스크톱 앱의 운영 절차를 정리한 문서입니다.

지원 사이트: 천유닷컴, 과자생각 한국어·일본어·영어 번역 일반·상세 수집 상세 탭 병렬 처리 장바구니 일괄 처리 상품·운송장 서버 POST 원-엔 환율 적용

1. 앱 개요

이 앱은 Electron과 Playwright를 사용하여 현재 PC에서 쇼핑몰에 로그인하고, 상품 목록·장바구니·상세페이지 데이터를 수집합니다.
수집 데이터는 한국어 원문을 기준으로 일본어와 영어 번역을 함께 관리하며, 상세 수집은 최대 10개의 브라우저 탭으로 병렬 처리합니다.
결과는 실행별 폴더에 CSV와 JSON으로 저장되고 상품 및 운송장 데이터는 지정 서버로 전송됩니다.

로컬 실행

브라우저 자동화와 파일 저장이 사용자의 PC에서 수행됩니다.

한·일·영 번역

기존 일본어 번역에 영어 번역을 추가하여 운송장 시스템과 데이터 형식을 통일합니다.

상세 탭 병렬 수집

상세 상품 수집 시 작업을 여러 탭에 분배하여 처리 속도를 높였습니다.

상품·운송장 서버 연동

수집 결과와 운송장 데이터를 각각 지정된 서버 전송 절차에 따라 POST합니다.

2026-08-17 주요 변경사항 (v1.3.0) ISP 프록시 아웃바운드 연결 및 재접속 안전장치, 영문 상세 페이지 진입 시 한국어 페이지 재접속 보정, 천유 상세 수집 항목(상품바코드·옵션바코드·원산지·소재·무게·포장사이즈) 및 hscode 키 추가, 시간별 원엔 환율 체크(00시 아카이브) 반영, 체크 누락 소단위 재시도와 품절 예외 처리, 프록시/API 키 사용 방식 변경
운영 전 확인 쇼핑몰 계정의 접근 권한, 로그인 가능 여부, 네트워크 상태를 먼저 확인하세요. 쇼핑몰 화면 구조가 변경되면 일부 selector를 수정해야 할 수 있습니다.

2. 빠른 시작

1 앱 실행

배포된 앱을 실행하거나 프로젝트 폴더에서 npm start를 실행합니다.

2 계정 등록

계정 등록 및 관리에서 사이트 로그인 계정을 저장합니다.

3 수집 설정

사이트, 계정, 일반·상세 방식과 페이지 범위를 지정합니다.

4 결과·전송 확인

실행 카드에서 한·일·영 번역, 저장 파일, 상품 결과 POST와 운송장 서버 응답을 확인합니다.

3. 계정 등록 및 관리

수집 설정의 계정 등록 및 관리 버튼에서 등록 이름, 로그인 ID, 비밀번호를 입력합니다. 등록한 계정은 수집용 계정과 장바구니용 사이트별 계정 선택 목록에 함께 표시됩니다.

등록 이름

화면에서 계정을 구분하기 위한 이름입니다. 예: 천유 운영계정, 과자 테스트계정

ID / PW

해당 쇼핑몰의 실제 로그인 정보입니다. 잘못 입력하면 로그인 확인 단계에서 실패합니다.

계정 저장 주의 등록 계정은 현재 앱의 로컬 저장소에 보관됩니다. 공용 PC에서는 사용하지 말고, 운영 배포 시에는 OS 자격 증명 저장소 또는 암호화 저장 방식으로 전환하는 것이 안전합니다.

고급 설정

시작 / 종료 페이지

일반 수집은 종료 페이지가 0이면 마지막 페이지를 자동 감지합니다. 상세 수집은 종료 페이지를 직접 입력하며 한 번에 최대 20페이지입니다.

상세 수집 모드

범위 내 전체 상품은 지정 범위를 모두 다시 수집합니다. 천유의 신규·상세 미수집 상품은 상세 수집 성공 이력이 없거나 이전 상세 수집에 실패한 상품만 수집합니다. 기능 도입 후 첫 실행에는 안전한 기준 생성을 위해 범위 내 기존 상품도 한 번 포함될 수 있습니다.

상세 페이지 지연

상세페이지 사이의 대기 시간입니다. 차단·부하가 우려되면 값을 높입니다.

5. 일반 수집과 상세 수집

일반 수집

목록과 장바구니 데이터를 중심으로 상품 ID, 상품명, 판매·품절 상태, 옵션명, 수량, 재고 요약 등을 수집합니다. 천유 일반 수집의 가격은 이미 연 장바구니 또는 옵션 팝업의 effectivePrice를 대표값으로 사용하므로 별도 상세페이지 요청이 추가되지 않습니다.

상세 수집

먼저 선택 범위의 일반 수집을 실행한 뒤 선택한 상세 수집 모드의 대상만 상세페이지에서 처리합니다. 각 상품의 상세페이지의 카테고리, 상품번호, 상품바코드, 옵션바코드, 원산지, 소재, 무게, 포장사이즈, 박스 수량, 소비자가, 상세 정보, 대표·상세 이미지 URL 등을 저장합니다.

사이트별 차이

사이트일반 재고 처리상세 이미지장바구니
천유닷컴 장바구니 옵션별 실제 구매 가능 수량을 확인합니다. 대표 원본 이미지와 상세 이미지 URL을 분리합니다. 상품과 옵션 ID를 기준으로 지정 수량을 선택합니다.
과자생각 목록의 판매 가능·품절 상태를 중심으로 처리합니다. 상품 대표 영역과 #detail 상세 영역을 구분합니다. 상품을 한 건씩 담고 장바구니 확인 후 다음 상품으로 진행합니다.

번역 필드 기준

필드내용사용 목적
nameKo쇼핑몰에서 수집한 한국어 상품명원본 데이터 및 검수 기준
nameJa일본어 번역 상품명일본어 서비스와 기존 상품 데이터 연동
nameEn영어 번역 상품명운송장 시스템과 영문 데이터 연동

번역 처리 원칙 동일한 상품명은 한 번만 번역하고, 해당 상품의 옵션 목록을 함께 전달해 일본어와 영어 옵션명을 일괄 생성합니다. 이를 통해 번역 호출 수와 토큰 사용량을 줄입니다.

6. 여러 수집 작업 동시 실행

수집이 진행 중이어도 다른 작업들을 추가로 수행할 수 있습니다.

CCDOME · 상세 수집 · 과자 운영계정
상세페이지 8 / 20 · 실행 시간 1m 42s
실행 중
체크 누락 대응 상세 수집 중 체크 단계 누락이 발생해도 전체 재시도를 피하고, 누락된 대상만 작은 단위로 재시도합니다. 로그인 후 불필요한 대기 구간을 줄여 수집 속도를 유지합니다.

실행 카드에서 가능한 작업

  • 각 작업의 사이트, 수집 방식, 계정, 진행 단계 확인
  • 특정 실행만 개별 취소
  • 완료한 실행의 결과 폴더 열기
  • 실행별 재고·요약·상품·상세 CSV 개별 저장

계정 단위 충돌 방지 규칙

상황허용 여부

천유 A계정 장바구니 처리 중 → 천유 B계정 수집 시작허용
천유 A계정 장바구니 처리 중 → 과자 A계정 수집 시작허용
천유 A계정 수집 중 → 천유 A계정 장바구니 시작제한
서로 다른 사이트·계정의 일반/상세 수집 여러 건허용

7. 장바구니 자동 담기

장바구니 UI에는 천유닷컴 계정, 과자생각 계정과 장바구니 담기 버튼만 표시됩니다. 사용자가 상품을 직접 입력하지 않고 Uploader 서버의 GET 응답 배열을 사용합니다.

사용 순서

  1. 천유 상품이 있을 경우 사용할 천유 계정을 선택합니다.
  2. 과자생각 상품이 있을 경우 사용할 과자생각 계정을 선택합니다.
  3. 장바구니 담기 버튼을 누릅니다.
  4. 앱이 Uploader 서버에 GET 요청을 한 번 보냅니다.
  5. 응답 배열을 사이트별로 분리하고, 각 사이트에 한 번 로그인합니다.
  6. 천유 상품은 옵션 단위로, 과자생각 상품은 한 상품씩 순차적으로 담습니다.
  7. 품절·재고 없음 항목은 해당 상품만 실패 처리하고 이어서 진행합니다.

GET 요청

GET https://www.web3.io.kr/joahstore/crawling/uploader

  }

실제 장바구니 담기
과자생각 처리 방식 여러 상품을 한 번에 제출하지 않습니다. 상품 상세 이동 → 수량 입력 → 장바구니 추가 → 장바구니에서 해당 상품 확인 → 다음 상품 순서로 처리합니다.
장바구니 예외 처리 수량 확인 API/DOM 동기화 실패, 품절, 옵션 미매칭은 각 상품 단위로 분기 처리하고 해당 상품만 별도 실패 사유로 기록 후 다음 상품을 계속 진행합니다.

8. 결과 파일

결과는 기본 출력 폴더 아래에 실행별 하위 폴더로 저장됩니다. 최근 완료 결과는 하단 결과 파일 영역에서, 개별 실행 결과는 실행 카드에서 저장할 수 있습니다.

파일생성 조건내용
inventory.csv항상옵션별 재고 또는 판매 가능 상태
summary.csv항상상품 단위 재고·옵션·가격 요약
products.csv항상수집한 전체 상품 목록과 한국어·일본어·영어 상품명
details.csv상세 수집 결과가 있을 때상세페이지의 상품 정보, 이미지 URL, 상품바코드/옵션바코드, 원산지, 소재, 무게, 포장사이즈, hscode
result.json항상수집 결과 객체와 상품·옵션별 한·일·영 번역
detailResult.json상세 수집 결과가 있을 때실제 상세 수집된 상품과 상세 정보·이미지·번역 데이터를 productId key로 구성, hscode 포함

JSON 저장 방식

수집 중 한 줄씩 파일에 추가하지 않습니다. 수집 데이터를 메모리에 모은 후 객체를 완성하고, 마지막 저장 단계에서 JSON 파일 전체를 한 번에 기록합니다.

상세 수집 모드와 결과 차이 상세 수집에서도 선행 일반 수집 결과에는 선택 범위의 상품이 모두 들어갈 수 있습니다. 신규·상세 미수집 상품 모드에서는 상세 성공 이력이 없는 상품과 이전 실패 상품만 상세페이지를 열며, 대상이 0건이어도 선행 일반 수집을 마친 뒤 정상 종료합니다. 상세 성공 상태는 쇼핑몰과 상품 ID를 기준으로 별도 보관하고, 부분 범위에서 관측되지 않은 상품을 삭제로 판단하지 않습니다. 상품명과 옵션명은 nameKo, nameJa, nameEn 필드로 저장되며, 수집 항목에 barcode, origin, material, weight, packageSize, hscode가 추가됩니다.

9. 상품 결과 및 운송장 서버 전송

CSV·JSON 파일 저장이 끝나면 파일을 다시 읽지 않고 메모리에 완성된 결과 객체를 POST합니다. 실제 로컬 JSON 파일은 그대로 유지하며, 상품 결과 전송용 복사본에서만 모든 productUrl 키를 제거합니다. 가격은 수집 시점의 최신 원엔 환율로 환산된 값 기준으로 반영되고, 운송장 데이터는 한국어·일본어·영어 상품명과 옵션명을 동일한 기준으로 정리해 전송합니다.

일반 결과

POST https://www.web3.io.kr/joahstore/crawling/uploader
Content-Type: application/json

{
  "type": "재고",
  "data": { /* productUrl이 제거된 result.json 데이터 */ }
}

상세 결과

{
  "type": "디테일",
  "data": { /* productUrl이 제거된 detailResult.json 데이터 */ }
}

10. 콘솔 로그 확인

장바구니와 결과 전송 상태는 Electron 실행 터미널과 Renderer 개발자 도구에서 확인합니다.

[CART UPLOADER RESPONSE]GET 응답으로 받은 전체 상품 배열
[CART cheonyu]천유 장바구니 진행 로그

개발자 도구

  • 개발 환경에서는 Electron 창의 개발자 도구 Console에서 Renderer 로그를 확인합니다.
  • Playwright, 로그인, 파일 저장, GET·POST 로그는 앱을 실행한 터미널에서 확인합니다.
  • 배포판에서 개발자 도구가 비활성화되어 있다면 로그 파일 또는 터미널 실행 방식으로 확인합니다.

11. 문제 해결

“로그인 성공 확인 실패”가 표시됩니다.
계정 ID/PW가 맞는지 확인하고 브라우저 표시를 ‘표시’로 변경해 실제 로그인 화면과 보안 인증 여부를 확인합니다. 사이트가 로그인 폼 또는 로그인 성공 문구를 변경한 경우 로그인 selector 수정이 필요합니다.
같은 계정으로 수집 또는 장바구니를 시작할 수 없습니다.
동일 사이트·동일 계정 작업이 이미 실행 중인 상태입니다. 해당 실행 카드가 끝나거나 취소된 후 다시 시도하세요. 다른 계정이나 다른 사이트 작업은 동시에 실행할 수 있습니다.
Uploader GET 응답에 상품이 없다고 나옵니다.
서버 주소 응답이 JSON 배열인지 확인하고, Electron 터미널의 [CART UPLOADER RESPONSE] 로그를 확인합니다. 각 항목에는 productId, optionId, quantity, site가 필요합니다.
과자생각에서 첫 상품만 담기거나 일부 상품이 누락됩니다.
최신 버전은 상품을 하나씩 처리하고 매번 장바구니에서 확인합니다. 누락 ID 오류가 표시되면 상품 상세의 수량 input, 장바구니 버튼 또는 장바구니 row selector가 현재 사이트 DOM과 일치하는지 확인합니다.
앱 접속 시 영문 페이지가 먼저 열립니다.
일부 네트워크 경로에서 영문 페이지가 응답하면 앱이 자동으로 한글 페이지로 재접속합니다. 로그의 [LANGUAGE REDIRECT] 항목을 확인하고, 사이트 언어 강제 옵션이 로그인 계정 정책과 일치하는지 점검하세요.
상세 이미지 URL이 비어 있습니다.
브라우저 표시 모드에서 상세 영역이 실제로 로드되는지 확인합니다. 과자생각은 대표 이미지 영역과 #detail 영역을 구분하며, 썸네일 경로는 제외합니다. 사이트의 lazy-load 속성 변경 여부도 확인하세요.
POST 요청 실패 후 결과 파일이 사라졌나요?
POST는 로컬 저장 이후 실행됩니다. 실행별 출력 폴더에서 result.json, detailResult.json과 CSV를 먼저 확인하세요. 단, 저장 단계 이전에 실패했다면 파일이 생성되지 않았을 수 있습니다.
결과 폴더 변경이 실행 중인 작업에도 적용되나요?
변경한 결과 기본 폴더는 변경 이후 새로 시작하는 실행부터 적용됩니다. 이미 실행 중인 작업은 시작 시점의 폴더 설정을 사용합니다.
Playwright 브라우저가 열리지 않습니다.
패키지 설치 상태와 Playwright 브라우저 파일을 확인하고, 소스 실행 환경에서는 의존성 설치 후 다시 시작합니다. 숨김 모드에서도 브라우저 프로세스는 실행되므로 터미널 오류를 확인하세요.
영어 상품명 또는 영어 옵션명이 비어 있습니다.
번역 요청 결과에 nameEn 또는 옵션별 en 값이 포함되었는지 확인합니다. 동일 상품 옵션을 묶어 번역하는 구조이므로 상품 ID와 옵션 ID가 번역 결과의 ID와 일치해야 합니다.
일반 수집에서 특정 상품만 누락됩니다.
체크 누락 항목은 소단위 재시도로 보완 처리됩니다. 재시도 후에도 실패하면 로그의 [RETRY DETAIL]와 페이지 오류를 함께 확인하세요.
상세 수집을 10탭으로 실행한 뒤 PC가 느려집니다.
브라우저 표시 모드, 이미지 로딩, PC 메모리 상태를 확인합니다. 운영 환경 성능이 낮으면 상세 동시 탭 수를 5개 이하로 낮추고 상세 페이지 지연 시간을 늘려 안정성을 우선합니다.
운송장 서버 전송이 실패합니다.
Electron 터미널의 [SHIPPING POST] 로그에서 요청 주소, 상태 코드와 응답 내용을 확인합니다. 운송장번호 누락, 상품 ID 연결 실패, 서버 인증값 또는 네트워크 오류 여부를 순서대로 점검합니다.

12. 보안 및 운영 주의사항

  • 쇼핑몰 계정 비밀번호를 GET query나 결과 JSON에 포함하지 않습니다.
  • 장바구니 Uploader GET은 상품 목록만 수신하고, 계정 정보는 로컬 로그인에만 사용합니다.
  • 결과 POST에는 수집 데이터만 전송하며 productUrl은 전송용 데이터에서 제거합니다.
  • 공용 PC에서 계정 등록 기능을 사용하지 않습니다.
  • 운영 계정으로 테스트하기 전에 별도 테스트 계정으로 selector와 수량 처리를 확인합니다.
  • 반복 실행 주기는 사이트 부하와 이용정책을 고려하여 충분한 간격으로 설정합니다.
  • ISP 프록시/API 키는 소스에 하드코딩하지 않고 환경 설정에서 관리합니다.
  • 환율 아카이브 파일은 실행 사용자 권한이 있는 경로만 접근하도록 제한합니다.
  • 영문 번역 데이터에는 계정 비밀번호나 서버 인증값을 포함하지 않습니다.
  • 운송장 서버 주소와 인증정보는 소스에 직접 노출하지 않고 운영 환경 설정으로 관리합니다.
  • 10탭 상세 수집 전 운영 PC의 메모리와 네트워크 상태를 확인합니다.
